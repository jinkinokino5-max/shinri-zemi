## 1. 参考3サイトのモーション実態

実際にブラウザで操作して確認した挙動。

| サイト | 観測されたモーション | 実装手段の推定 |
|---|---|---|
| blancavillalobos.com | 作品行がフルブリードで縦に並び、スクロールに応じて次の行が**前の行の上に重なって迫り上がる**（キャプションは行の上端に貼り付く）。ページ全長7,831px | `position: sticky` の重ね／Webflowインタラクション |
| nexusmag.eu | 初回表示時に**プリローダーで白紙 → 要素が順に出現**（実測：ナビゲート後3秒間は白紙のまま、4秒待って初めて描画された）。ヒーローの斜線は静止 | Framerの入場アニメーション |
| techyscouts.com | ヒーローのマスコットが微細に浮遊。スクロールでセクションが切り替わる | GSAP系と推定（未確定） |

> **注釈：nexusmag は「4秒待たないと何も見えない」状態だった。**
> 本件の最優先読者は**スポンサー・外部の大人**なので、これは真似してはいけない。
> スポンサーは回遊せず、1回見て判断する。**初回描画が遅いサイトは、それだけで機会を失う。**
> → 本件の原則：**「凝った入場演出は使うが、コンテンツは最初から見えている」**。フェードインは要素が既にレイアウトされた状態から始める（`opacity` と `transform` のみを動かし、`display:none` からは始めない）。

## 2. 2026年時点で使える「JSゼロ」のモーション技術

出典：
- [CSS Scroll-Driven Animations Guide (2026) — CSSAWWWARDS](https://cssawwwards.com/blog/css-scroll-driven-animations-guide-2026)
- [View Transitions API and CSS Scroll-Driven Animations: The Browser Wins of 2026 — Frontend Horizon](https://www.frontendhorizon.com/blog/view-transitions-api-and-css-scroll-driven-animations-the-browser-wins-of-2026)
- [Scroll-Driven Animations — Josh W. Comeau](https://www.joshwcomeau.com/animation/scroll-driven-animations/)
- [Native CSS Scroll-Driven Animations in 2026 — Mintec](https://mintec.co/blog/css-scroll-driven-animacion/)

### ① スクロール駆動アニメーション（`animation-timeline`）

上記出典によれば、Chrome/Edge 115+、Firefox 132+、Safari 18+ が対応し、2026年時点でクロスブラウザのベースラインに到達。グローバル対応率は約84%（2026年半ば時点）。
**※この対応率は出典の記述であり、私が独自に検証したものではない。実装前に caniuse で再確認すること。**

```css
/* スクロール量に連動する進捗バー（記事の読み進みインジケータ） */
@keyframes grow { from { scale: 0 1 } to { scale: 1 1 } }
.progress {
  animation: grow linear both;
  animation-timeline: scroll();      /* ← ページ全体のスクロールに連動 */
  transform-origin: left;
}

/* 要素が画面に入ってきたら出現（IntersectionObserver不要） */
@keyframes reveal {
  from { opacity: 0; translate: 0 2rem }
  to   { opacity: 1; translate: 0 0 }
}
.card {
  animation: reveal linear both;
  animation-timeline: view();        /* ← その要素自身の可視状態に連動 */
  animation-range: entry 0% cover 30%;
}
```

**利点**：
- JavaScript **0KB**。GSAP（約70KB）や Lenis を入れなくてよい。
- コンポジタスレッドで動くため、スクロールと同じ滑らかさになる。
- 未対応ブラウザでは**アニメーションが効かないだけ**で、コンテンツは普通に表示される（＝安全に劣化する）。

> **注釈：本件は「まず静的、あとで拡張」方針なので、JSライブラリへの依存を減らせる意義が大きい。**
> 学生が後から引き継ぐことを考えると、GSAPのタイムライン記述を読める人が必要になる構成は避けたい。
> **CSSだけで書いてあれば、引き継ぎコストが桁違いに低い。**

### ② View Transitions API（ページ遷移の演出）

```css
@view-transition { navigation: auto; }   /* これだけでページ間がクロスフェードする */

/* 作品サムネ → 作品詳細ページで、画像が「continuous」に飛ぶ */
.thumb  { view-transition-name: work-hero; }
```

- 参考サイト blancavillalobos.com の「ぬるっとしたページ遷移」の現代的な代替。
- **注釈：作品集の一覧 → 詳細で、サムネイルがそのまま拡大して詳細のヒーロー画像になる、という動きが数行で書ける。** これは「見せたくなるサイト」の体験として非常に強い。学生が自分の作品ページをスマホで友達に見せるとき、この1つの動きが効く。

### ③ `position: sticky` の重ね（blancavillalobos.com の作品行）
```css
.work { position: sticky; top: 0; height: 100svh; }
```
- ライブラリ不要。作品を1件ずつ全画面で「めくる」体験になる。
- **注釈：これは blanca のサイトで最も印象的だった仕掛けで、実装コストはほぼゼロ。**

## 3. 「妄想」層で使えるインタラクションのアイデア（Mission連動）

Mission「大学生の溢れ出す妄想を形にする」／Vision「北大で最も大量におもろいことが生まれる場所になる」を、**装飾ではなく構造で**表現する案。

| # | アイデア | 実装コスト | Vision/Missionとの対応 |
|---|---|---|---|
| 1 | **トップに部活・PJ・イベントのピルを大量に散らす**（nexusmag のタグ群を拡張）。数が増えるほど画面が埋まる | 低（CSSのみ） | 「大量におもろいことが生まれる」を**実際の件数で証明**する。最推奨 |
| 2 | **カウンタ**：部活◯個／PJ◯個／今年の企画◯本 を巨大な数字で | 低 | スポンサー向けの説得力。数字は必ず実データを入れること（捏造しない） |
| 3 | **「妄想」→「形」のトグル**：作品カードをホバー/タップすると、企画時のラフ・メモと完成物が入れ替わる | 中 | Missionそのもの。**本件で最も"ならでは"になる仕掛け** |
| 4 | 部活タグをクリックすると、作品グリッドがその部活の色に染まる | 中 | 5タブの横断導線 |
| 5 | スクロールに応じて地の色が生成り→墨に反転（二層構造の切替を体感させる） | 低 | 決定済みの二層構造を明示 |

> **注釈：#3 は他に類例を見なかった。** 参考70件を見た限り、「制作過程と完成物を対で見せる」エディトリアルサイトは存在したが、**1つのカードの中で入れ替える**形は見つからなかった。本件の独自性を作るならここ。
> ただし運用上、学生に「ラフ画像も出してもらう」必要が生じる。投稿フォームの設計に影響するため、次のヒアリングで確認したい。

## 4. 守るべき制約

### `prefers-reduced-motion` は必須
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```
- 前庭障害・偏頭痛のある人にとって、大きなパララックスは実害がある。
- **注釈：これは倫理上の配慮であると同時に、「大学の団体として外部に出すサイト」の最低限の品格でもある。5行で済む。**

### イージングとタイミング
参考3サイトから読み取れる共通の感覚：

| 用途 | 推奨 duration | 推奨 easing |
|---|---|---|
| ホバー（色・下線） | 150–200ms | `ease-out` |
| カードの出現 | 400–600ms | `cubic-bezier(.16,1,.3,1)`（＝expo out。**現代的な"ぬるっと"の正体**） |
| ページ遷移 | 300–500ms | `cubic-bezier(.65,0,.35,1)` |
| 装飾の浮遊 | 3–6s ループ | `ease-in-out` |

- **注釈：`cubic-bezier(.16,1,.3,1)` は「最初に速く動き、最後に長く減速する」曲線。** アーティスティック系サイトの上質さの多くは、色でも書体でもなくこの曲線に由来する。**覚えておく価値のある1行。**

### モーションの総量
- **1画面に同時に動く要素は3つまで。** それ以上は「賑やか」ではなく「安っぽい」になる。
- 「妄想」層（トップ・団体紹介）は動きを多く、「静謐」層（作品集・PJ）は**ホバー以外ほぼ動かさない**。これが二層構造の本質。
