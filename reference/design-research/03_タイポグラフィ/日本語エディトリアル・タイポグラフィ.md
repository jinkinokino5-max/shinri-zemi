## 3. 日本語フォントの重さ問題 ——「実測してみた」

**よくある誤解：「日本語フォントは数MBあるから、Webフォントは使えない」**
→ **これは Google Fonts に関しては誤り。** 実測で確認した。

### 実測手順と結果

`Zen Kaku Gothic New` の 400 と 700 を Google Fonts CSS2 API で読み込むCSSを取得（2026-08-09時点）：

```
CSSファイル自体のサイズ : 224,446 bytes
@font-face の数         : 242
unicode-range の数      : 242  （＝1ウェイトあたり121分割）
```

つまり Google Fonts は**日本語フォントを121個のスライスに自動分割**し、`unicode-range` で「そのページに出てくる文字が含まれるスライスだけ」を落とす仕組みになっている。

さらに、実際にスライスを11個ダウンロードして計測：

```
slice 2   :    932 bytes
slice 14  : 17,016 bytes
slice 26  : 14,436 bytes
slice 38  : 13,696 bytes
slice 50  :  6,816 bytes
slice 62  :  9,844 bytes
slice 74  :  9,104 bytes
slice 86  :  8,796 bytes
slice 98  :  9,676 bytes
slice 110 :  8,152 bytes
（+1件）
────────────────────────
平均       :  9,838 bytes ≒ 約10KB / スライス
```

### 結論と設計への反映

- 一般的な日本語ページは 15〜30 スライス程度を必要とする → **1ウェイトあたり約 150〜300KB**。
- **2ウェイト（Regular + Bold）に絞れば 300〜600KB** で収まる。これは高解像度写真1枚分と同程度。
- **注釈：したがって本件では「日本語Webフォントを使わない」という妥協は不要。** ただし以下は守ること。
  1. **ウェイトは2つまで**（400と700）。可変フォントを選ぶ場合は1ファイルで済むので `Murecho`（1,397KB・可変）が最軽量候補。
  2. **書体は和文1つに絞る**。和文2書体＝転送量2倍。明朝とゴシックの両方が欲しい場合は、**片方を「見出し限定・少数の文字だけ」に使う**（見出しは文字数が少ないので必要スライスも少ない）。
  3. CSS自体が224KBある点に注意。`preconnect` を必ず入れる。
  4. 本気で軽くするなら、**サブセット済みフォントをセルフホスト**する（後述の 06 フォルダ参照）。

## 4. 日本語で「エディトリアル」を成立させる7つの技術

参考3サイトの実測値は**すべて欧文前提**なので、そのまま日本語に適用すると失敗する。以下は日本語に翻訳した設定。

### ① 行間（line-height）— 欧文の値をそのまま使わない
- 参考サイト実測：nexusmag H1 = 45px/45px（**1.0**）、techyscouts H2 = 48px/48px（**1.0**）
- **日本語は仮名・漢字が正方形に詰まるため、1.0では窒息する。**

| 用途 | 欧文の定石 | **日本語での推奨** |
|---|---|---|
| 大見出し（40px超） | 1.0 | **1.15 〜 1.25** |
| 中見出し | 1.1 | **1.4** |
| 本文 | 1.5 | **1.7 〜 1.9**（漢字が多いほど広く） |
| キャプション | 1.4 | **1.6** |

### ② 字間（letter-spacing）
- 参考サイト実測：nexusmag H2 = **−1.24px（−0.04em）**
- 日本語も**見出しは必ず詰める**。ただし −0.04em は詰めすぎ。

| 用途 | 推奨値 |
|---|---|
| 大見出し（和文） | **−0.02em 〜 −0.03em** |
| 本文（和文） | **0.07em 〜 0.10em** ← 下の実測を受けて修正 |
| 小ラベル・全大文字英字 | **0.08em 〜 0.15em**（大きく開ける＝雑誌の柱の質感） |

#### ⚠ 実測による重要な修正（欧文の定石をそのまま持ち込むと失敗する）

日本のデザイン系サイト2件を実ブラウザで計測したところ、**欧文サイトよりはるかに字間・行間を広く取っている**ことが分かった。当初この資料に書いた「本文 0.02〜0.04em」は狭すぎたため、上表を修正した。

| サイト | 対象 | font-size | line-height | letter-spacing |
|---|---|---|---|---|
| **武蔵野美術大学 卒業制作優秀作品集**（selected.musabi.ac.jp） | 本文 | 16px | **32px＝2.00** | **1.6px＝0.10em** |
| 同上 | 学科名（H3） | 17px | **42.5px＝2.50** | 1.6px＝0.094em |
| **JAGDA**（日本グラフィックデザイン協会） | 本文（p） | 14px | **25.2px＝1.80** | **1px＝0.071em** |
| 同上 | 記事見出し（H3） | 20px | **40px＝2.00** | 1.5px＝0.075em |

**注釈：日本のトップクラスのデザイン系サイトは、行間1.8〜2.5・字間0.07〜0.10em を採用している。**
欧文エディトリアル（nexusmag の line-height 1.0 など）とは正反対の方向であり、**「詰める」ことが上質さだと思って日本語に適用すると、逆に安っぽくなる**。
和文は「ゆったり組む」ことが品格になる。ただし**大見出しだけは詰める**（漢字が並ぶと隙間が空いて見えるため）。この使い分けが日本語エディトリアルの核心。

#### 実測で判明したもう一つの事実：和欧混植の順序は実務でも標準

両サイトとも `font-family` の**先頭に欧文書体を置き、その後ろに和文書体を並べていた**（下記⑤で推奨した手法と完全に一致）。

```
JAGDA:
  aktiv-grotesk, a-otf-gothic-bbb-pr6n, 游ゴシック体, "Yu Gothic", ...
  └欧文グロテスク    └中ゴシックBBB（モリサワ）  └OS標準フォールバック

武蔵野美術大学:
  a-otf-futo-go-b101-pr6n, 游ゴシック, YuGothic, "ヒラギノ角ゴ Pro", メイリオ, ...
  └太ゴB101（モリサワ）
```

- どちらも **Adobe Fonts 経由のモリサワ書体（有料）** を使っている。無料で同等を狙うなら、中ゴシックBBB ≒ `Zen Kaku Gothic New`、太ゴB101 ≒ `Zen Kaku Gothic New Bold` / `Dela Gothic One` が近い。
- **注釈：Adobe Fonts は Creative Cloud 契約があればWebフォントとして使える。** 本件でモリサワ書体を使えるかは契約状況次第。次のヒアリングで確認したい（無料書体だけでも十分成立する前提で設計は進める）。

**武蔵野美術大学のサイトは、色が黒（975箇所）と白（34箇所）の2色のみで構成されていた。**
書体1つ・色2つ・広い字間と行間——それだけで日本語エディトリアルとして完成している。本件でも「引き算」を最初の設計原則に置くべき根拠になる。

### ③ 約物（句読点・括弧）の余白を詰める
日本語の `、。（）「」` は前後に大きな空きを持つ。放置すると見出しがガタつく。
```css
h1, h2, h3 { font-feature-settings: "palt" 1; }  /* プロポーショナルメトリクス */
```
- **注釈：`palt` は日本語組版の質を最も安く上げる1行。** Google Fonts の日本語書体の多くが対応している（Zen Kaku Gothic New、Shippori Mincho は対応）。**必ず入れる。**

### ④ 禁則処理と改行位置
```css
body { line-break: strict; overflow-wrap: anywhere; }
h1, h2, .lead { word-break: auto-phrase; }  /* 文節で改行（Chrome 119+）*/
```
- `word-break: auto-phrase` は**日本語の文節を認識して改行位置を決める**新機能。見出しが「北大心理ゼ／ミ」のように割れるのを防ぐ。
- 未対応ブラウザでは無視されるだけなので、入れて損はない。
- より確実にやるなら、見出しは手で `<br>` を入れるか `<wbr>` を打つ。

### ⑤ 和欧混植の調整
和文書体の欧文グリフは概して品質が低い。**欧文だけ別書体に差し替える**のが定石。
```css
body {
  font-family:
    "Switzer",            /* 欧文・数字はこれ */
    "Zen Kaku Gothic New",/* 和文はこれ */
    sans-serif;
}
```
- **注釈：font-family の順序＝「先に書いた書体が持っている文字はそれで表示される」。** 欧文書体を先に書くことで、英数字だけが欧文書体になる。この1行だけで「日本語サイトなのに垢抜けて見える」効果が出る。**本件で必ず使う。**

### ⑥ 縦組み（writing-mode）を1箇所だけ使う
```css
.vertical { writing-mode: vertical-rl; font-feature-settings: "vpal" 1; }
```
- 全面縦組みは可読性・実装コストともに割に合わない。
- **注釈：ただし「作品タイトル1本だけを縦に置く」「セクションの柱を縦にする」なら、コスト最小で最大の"雑誌"効果が出る。** 参考にした blancavillalobos.com の左カラムラベルを、日本語では縦組みにするのが本件の推奨。

### ⑦ 数字はモノスペースかつ等幅数字に
```css
.meta { font-family: "Space Mono", "M PLUS 1 Code", monospace; font-variant-numeric: tabular-nums; }
```
- 事例カタログの法則1（モノスペースのラベル）を日本語で実現する。
- 日付・番号・人数が縦に揃うだけで、一覧の見え方が一段上がる。

## 5. 本件での推奨フォント構成（3案）

### 案A：モダン・エディトリアル（推奨）
```css
--font-display : "Oi", "Dela Gothic One", sans-serif;        /* 英語大見出しのみ */
--font-sans    : "Switzer", "Zen Kaku Gothic New", sans-serif;
--font-serif   : "Instrument Serif", "Shippori Mincho", serif; /* 引用・情緒 */
--font-mono    : "Space Mono", "M PLUS 1 Code", monospace;    /* ラベル・数値 */
```
- 転送量目安：和文2書体×2ウェイト＝約600KB〜900KB。**やや重い。** 明朝は引用と見出しだけに限定して抑える。

### 案B：軽量重視
```css
--font-sans : "Switzer", "Murecho", sans-serif;   /* Murecho=可変・1.4MB原本 */
--font-mono : "Space Mono", monospace;
```
- 和文1書体（可変）のみ。**最軽量。** ウェイトの幅で階層を作る。

### 案C：明朝主軸（最もアート寄り）
```css
--font-display : "Hina Mincho", serif;      /* 極細明朝の巨大見出し */
--font-sans    : "Switzer", "Zen Kaku Gothic Antique", sans-serif;
--font-mono    : "Space Mono", monospace;
```
- MaxiBestOf の「5th Management（PMincho一本）」型。**最も「作品集」らしくなるが、団体紹介の情報量には向かない。**

**注釈：二層構造（決定済み）を考えると、「作品集・PJ＝案C寄り」「トップ・団体紹介＝案A寄り」という使い分けが理屈上は最適。ただし書体が増えるほど重くなるため、次のヒアリングで優先順位を確認したい。**
