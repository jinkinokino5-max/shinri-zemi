[Astro 5 vs Next.js 15: Best for Content Sites 2026 — PkgPulse](https://www.pkgpulse.com/guides/astro-5-vs-nextjs-15-content-sites-2026) ／

※以下の性能数値は上記出典の記述であり、私が本件の環境で計測したものではない。

| 観点 | **Astro** | Next.js | Vite＋素のHTML/CSS/JS |
|---|---|---|---|
| JS配信量 | 既定で **0KB**（必要な箇所だけ島として動かす） | Reactランタイムが常に乗る | 自分で書いた分だけ |

## 3. 推奨：**Astro**

### 理由（本件の条件に紐づけて）

**① 「まず静的、あとで拡張」に最も素直に対応する**
Content Collections で作品データを Markdown＋フロントマターとして持てば、
- 今：ファイルを置くだけで作品が増える
- 将来：同じスキーマのまま microCMS や Notion に差し替えられる（データ構造を作り直さなくてよい）

```markdown
---
title: "豆腐ゲーム"
category: "PJ"          # PJ | 部活 | イベント
club: "豆腐ゲームPJ"
authors: ["○○", "△△"]
year: 2026
cover: "./tofu.jpg"      # 空でもよい → 灰色ブロックにフォールバック
sketch: "./tofu-rough.jpg"  # 「妄想」画像（モーション資料の案#3用）
---
制作の経緯をここに書く。
```
- Zod スキーマで検証されるため、**学生が項目名を間違えるとビルドが失敗して教えてくれる**。運用事故を仕組みで防げる。

**② JSが0KBで済む＝スポンサーが最初の1回で必ず見られる**
モーション資料で調べた通り、2026年時点ではスクロール演出も**CSSだけ**で書ける。GSAP等を入れる必要がない。
nexusmag が「4秒間まっ白」だった失敗を、構造的に回避できる。

**③ 引き継ぎコストが最小**
本件は**大学生の団体**であり、代表・副代表の任期は5月末まで（＝毎年入れ替わる）。
「Markdownを書けば作品が増える」構成なら、Reactを知らない後輩でも運用を続けられる。
**これは技術的な優劣ではなく、組織構造から導かれる要件。**

**④ 島（Islands）で必要な箇所だけ動的にできる**
作品集の絞り込み（nexusmag のフィルタバー相当）だけ、後から React や Svelte の島として足せる。全体をSPAにする必要がない。

### Astro を選ぶことのリスク（正直に記載）
- **将来「学生がログインして投稿する」まで作るなら、Next.js の方が近道。** Astro でも可能だが、SSRアダプタ＋認証の構成を自前で組むことになる。
- 現時点の決定は「まず静的、あとで拡張」なので Astro が最適だが、**もし1年以内に投稿機能まで確実に作ると決まっているなら、最初から Next.js にする方が総工数は小さい。**
- → **次のヒアリングでこの点を確認したい。**

## 4. 推奨構成（案）

```
北大心理ゼミ website/
├ src/
│  ├ content/
│  │  ├ works/        作品（Markdown＋画像）
│  │  ├ clubs/        部活
│  │  ├ projects/     PJ
│  │  ├ events/       イベント
│  │  └ config.ts     Zodスキーマ定義
│  ├ components/
│  ├ layouts/
│  ├ pages/
│  │  ├ index.astro           トップ
│  │  ├ works/[...slug].astro 作品集
│  │  ├ events/
│  │  ├ clubs/
│  │  ├ projects/
│  │  └ about.astro           団体紹介
│  └ styles/
│     ├ tokens.css    色・書体・余白の変数（04と03の資料を反映）
│     └ base.css
├ public/
└ astro.config.mjs
```

### ホスティング
| 候補 | 無料枠 | 独自ドメイン | 備考 |
|---|---|---|---|
| **Cloudflare Pages** | 帯域無制限 | 可 | **最推奨。** 学生団体で写真が増えても課金リスクが低い |
| Vercel | 商用利用は有料 | 可 | 学生団体は非商用と解釈できるが、スポンサー掲載があると微妙 |
| Netlify | 帯域100GB/月 | 可 | 十分だが上限あり |

> **注釈：Cloudflare Pages を推す理由は、スポンサーのロゴを載せた瞬間に「商用」と見なされる可能性を避けるため。** Vercel の無料プラン（Hobby）は商用利用を認めていない。**スポンサー獲得が目的の一つである本件では、ここは実務上のリスクになる。**（規約は変わりうるので、実装時点で必ず最新の利用規約を確認すること。）

## 5. Adobe Fonts（モリサワ書体）について

07フォルダで判明した通り、武蔵野美術大学もJAGDAも**Adobe Fonts経由のモリサワ書体**を使っている。
- Adobe Creative Cloud の契約があれば、Webフォントとして無料で使える（追加課金なし）。
- ただし**Adobe のサーバーからJSで読み込むため、表示が一段遅くなる**（＝スポンサー向けには不利に働く可能性がある）。
- **注釈：本件は Google Fonts の無料書体だけで十分成立する設計にしておき、CC契約があれば書体を差し替えるだけで質が上がる、という構成にするのが安全。** 03フォルダの推奨案はそうなっている。
