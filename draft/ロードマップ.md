#### ⚠ 1-E で判明した制約（重要）

`output: 'export'` では **`next/image` の最適化が使えません**（最適化サーバーが存在しないため
`images.unoptimized: true` が必須）。つまり **WebP/AVIF 変換・srcset 生成は効きません。**

一方 `06資料 3章` は「**学生の未加工写真が最大の負荷。ビルド時に自動最適化すること**」を
必須としており、その理由も明記されています。

> 「これは『学生に画像を圧縮してから入れてもらう』という運用ルールより、はるかに確実。
>   人に依存するルールは必ず守られなくなる。仕組みで解決する。」

**→ 代替：`sharp` による自前のビルド前処理に切り替えます。**

```
scripts/optimize-images.mjs   元画像 → WebP/AVIF ＋ 複数幅を生成
components/Picture.tsx        <picture> ＋ srcset ＋ width/height を出力
```

⚠ **現時点で写真が1枚も無いため、この実装は保留しています。**
今作っても検証できず、写真の実物（サイズ・比率・枚数）が分かってから作るほうが確実です。
**写真が来た時点で着手します。**（`sharp` は導入済み）

#### ✅ 決定：部活の独自ページのURL＝案A（2026-08-10）

**1部活＝1URL。**`/clubs/dokusho/` だけを持ちます。
独自ページを作った部活は**それがそのままこのURLの中身になり**、作らない部活は共通テンプレートで表示されます。

| 案 | URL | 内容 |
|---|---|---|
| **A ✅採用** | `/clubs/dokusho/` **1つだけ** | 独自ページを作った部活は**それがそのままこのURLの中身になる**。作らない部活は共通テンプレートで表示 |
| B | `/clubs/dokusho/` ＋ `/clubs/dokusho/original/` | 共通ページと独自ページを並立させる（不採用） |

採用の理由は3つ。

3. Bだと「どっちが本物か」が生まれ、**共通ページ側が更新されずに古い情報が残ります**

どちらの場合も、R-2の帯（「北大心理ゼミ ／ 一覧へ戻る」）は**団体側が自動で差し込み、部活は消せません。**

### 1-3. データスキーマ（⚠ ここが後から変えにくい）

`08資料` の Content Collections の考え方を、Next.js の Markdown 読み込みに移植します。

```ts
/* ⚠ 2026-08-10 追加：部活も終了する。status を Club にも持たせる。
   状態を持つのは Club / Project / Event の3種。Work（作品）は完成物なので状態を持たない。 */
type Status = "active" | "done";

type Club    = { slug; name; status: Status; foundedYear?; endedYear?;
                 leader?; memberCount?; body; cover? };
type Project = { slug; name; status: Status; purpose?; period?; members?; body; cover? };
type Event   = { slug; name; date; organizer?; audience?; body; cover? };
type Work    = { slug; title; displayNames: string[]; belongsTo; year; body; cover?; tags? };
```

⚠ **終了したものを削除しない。**`status: "done"` に変えるだけにします。3つの理由があります。

1. Value **「過去から学ぶことを忘れない」** が、データの持ち方として実装される
2. **終了した部活・PJに紐づく作品が、リンク切れにならない**（削除すると作品の所属先が消える）
3. スポンサーに対して、**活動の積み重ねが数字で示せる**（「PJ 進行中6／終了4」）

⚠ **`cover` は必ず optional。**空のとき `--paper-card` 地＋名前だけに切り替わります（大本資料 6-4／`musabi_02_category_grid.jpg` が実際にこの処理をしている）。
⚠ **数値も optional。**分からない数字を `0` で埋めません（CLAUDE.md 3-4）。
⚠ **制作者は `displayNames` の1項目だけ持ち、本名は保存しません。**本人選択制（B-1）なので、保存しなければ漏れません。

#### ⚠ ここで、公開を止めうるバグを1つ踏みました

**`output:'export'` は「動的ルートは最低1件を生成すること」を要求します。**
`generateStaticParams()` が空配列を返すとビルドが落ちます。

**作品は8月の公開時点で0件です。**つまりこのページを足した瞬間、
**サイト全体がビルドできなくなりました**（実際に落ちた）。部活・PJ・イベントは
中身があるので当たらず、作品だけが当たる罠です。

**対処：**0件のときだけ置き石を1つ生成し、**ビルド後に取り除く**
（`scripts/clean-works-placeholder.mjs` を `postbuild` で自動実行）。

> ▸ **「検査の例外にする」という直し方を選びませんでした。**
> 置き石は静的書き出しでは `lang` も `h1` も持たない簡易シェルになり、検査に落ちます。
> そこで検査を緩めると、その穴は二度と塞がれません。実際、`sitemap.xml` が検査対象外
> だったせいで404のURLを公開していたことに誰も気づきませんでした（同日発覚）。
> **出力しないほうを選び、検査は厳しいまま保ちます。**

**確認：**作品0件／1件 × ローカル／本番相当（`BASE_PATH`）の**4通りすべてでビルドと検査が通過。**
置き石はどこからもリンクされず、sitemap にも載りません。

#### この決定に伴って手当てすること（2点）

**① 作品集の一覧ページは、これまでどおり静かに保つ。**

大本資料 原理2 はこう書いています。

> 作品集とPJページは、逆に**極限まで引く**。装飾ゼロ、余白最大、色は墨と生成りだけ。
> ▸ なぜ：**学生の作品は色も雰囲気もバラバラだから、サイト側が主張すると全部が濁る**

この原理は **一覧ページ（`/works/`）に対して**適用します。
一覧が静かであれば、個々の作品ページがどれだけ賑やかでも全体は濁りません。
**個別ページは、作者本人の表現の場**として自由にします。原理2との衝突は、この線引きで回避できます。

**② 確認の負担を、機械で肩代わりする。**

公開前の確認は代表1人（F-8）で、任期は1年です。作品は件数に上限がないため、
**人の目だけに頼ると必ず形骸化します**（形骸化した確認は、無いより危険です）。

→ **`scripts/check-custom-pages.mjs` を用意しました。** 機械で判定できることは全部自動化し、
代表には**人にしか判断できないことだけ**を残します。

| 機械が見る（自動・不合格ならデプロイしない） | 人が見る（代表） |
|---|---|
| `<script>`・`onclick` 等のJSが無いか（R-1） | 写っている人の許可は取れているか |
| 外部サイトの画像・CSS・フォントを読んでいないか（R-3） | 拾い画像・他人の著作物が無いか |
| 容量が上限内か（R-5） | 掲載ポリシー（B-1〜B-5）に反していないか |
| 「一覧へ戻る」の帯があるか（R-2） | 内容が団体として出して問題ないか |
| `<h1>` があるか・`alt` があるか・文字化けしないか | |

**これで代表の作業は「読んで判断する」だけになります。**技術的な不備の指摘は機械が済ませます。

## 2. 引き継ぎ：この設計の隠れた最重要制約

> 代表・副代表の任期は**新歓終了の5月末まで**（`学生団体基本情報.txt` 3章）。
> **毎年、運営が入れ替わります。**

`08資料` はこう書いています。

> 「これは技術的な優劣ではなく、**組織構造から導かれる要件**」

このロードマップは、それに対して4つの手を打っています。

| # | 手 | 効果 |
|---|---|---|
| 1 | **JSライブラリを使わない**（CSSのみ） | GSAPを読める後輩がいなくても運用が続く |
| 2 | **Markdownを1つ足せば項目が増える**構造 | Reactを知らなくても更新できる |
| 3 | **設計の根拠を全部文書に残す** | 「なぜこの色か」を次の代表が資料で辿れる |
| 4 | **代表のチェック観点をリスト化**（P4-D） | 担当者が替わっても確認の質が落ちない |

⚠ **P5で「更新担当者」（F-6）を決めてください。**これが決まらないと、1年後にサイトが止まります。
