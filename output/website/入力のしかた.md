# 入力のしかた

このフォルダの中を書き換えると、サイトに反映されます。

---

## いま何が足りないかを見る

```
npm run status
```

「どのファイルの、何が空か」が一覧で出ます。**まずこれを実行してください。**

> ⚠ 空のままでもサイトは正しく表示されます。急いで全部埋める必要はありません。
> 分からない数字を **0 や適当な値で埋めないでください。**
> サイトには「––」と出ます。これは弱点ではなく、誠実さとして機能します。

---

## 1. 紹介文を書く（いちばん効果が大きい）

書き換えるファイル：

| 何を | どこ |
|---|---|
| 部活の紹介文 | `content/clubs/○○.md` |
| PJの紹介文 | `content/projects/○○.md` |
| イベントの内容 | `content/events/○○.md` |

ファイルを開くと、下のほうに `<!-- ここに書いてください -->` があります。
**その部分を、書きたい文章に置き換えてください。**

```markdown
---
name: "読書部"
status: "active"
foundedYearMonth: "2026-04"
---

月に一度集まって、各自が読んだ本を持ち寄っています。
ジャンルの指定はありません。小説でも新書でも漫画でもかまいません。
「人がおもしろいと思ったものを聞く時間がいちばん楽しい」という理由で
はじまりました。読むのが速くなくても大丈夫です。
```

**100〜300字くらいがいちばんきれいに収まります。**
短すぎると余白が間延びし、長すぎると読まれません。

書くとよいこと：

- どんな活動をしているか
- **なぜこの部活／PJをつくったのか** ← ここがいちばん読まれます
- どんな人に来てほしいか

---

## 2. 写真を入れる

**加工は不要です。撮ったままで大丈夫です。**
サイト側で白黒にして朱色を重ねる処理をかけるので、明るさや色がバラバラでも見た目が揃います。
マウスを乗せた1枚だけが元の色に戻ります。

### 手順

**① 写真を置く**

```
public/photos/clubs/dokusho/1.jpg      ← 読書部の写真
public/photos/projects/tofu-game/1.jpg ← 豆腐ゲームPJの写真
public/photos/events/doto/1.jpg        ← 道東合宿の写真
```

フォルダ名は `content/` の中のファイル名と同じにしてください（読書部なら `dokusho`）。
フォルダが無ければ自分でつくってかまいません。

**② `.md` ファイルの `cover:` の `#` を外す**

```yaml
# 変更前
# cover:
#   src: "/photos/clubs/dokusho/1.jpg"
#   alt: "読書部の活動のようす"

# 変更後
cover:
  src: "/photos/clubs/dokusho/1.jpg"
  alt: "読書部の活動のようす"
```

`alt` には「写真に何が写っているか」を短く書いてください。
目の見えない方の読み上げと、検索で使われます。

**横長（16:9くらい）の写真がいちばんきれいに収まります。**

### ⚠ 気をつけること

- 人の顔が写っている場合、**本人の許可**を取ってください
- 他の人が撮った写真を使う場合、**撮影者の許可**が要ります
- ネットで拾った画像は使えません

## 3. 部活・PJを増やす／終わったことにする

### 増やす

`content/clubs/` に新しいファイルを1つ作ります。ファイル名は**半角英数字とハイフンだけ**にしてください（これがURLになります）。

```yaml
---
name: "新しい部活の名前"
status: "active"
foundedYearMonth: "2026-04"
---

紹介文
```

### 終わったことにする

**消さないでください。** `status` を書き換えるだけです。

```yaml
status: "done"
endedYearMonth: "2026-06"
```

一覧の「これまでにやったこと」に移ります。
消してしまうと、その部活・PJに紐づいた作品のリンクが切れます。

---

## 4. 書き換えたあと

```
npm run status   いま何が足りないかを見る
npm run build    サイトをつくる
npm run check    公開してよい状態か検査する
```

**GitHubにpushすると、自動でビルド・検査・公開までされます。**
検査で問題が見つかった場合は公開されません（壊れたまま公開されるのを防ぐためです）。

---

## 書き方でつまずきやすいところ

| よくある間違い | 正しい書き方 |
|---|---|
| `name: 読書部` | `name: "読書部"` （`"` で囲む） |
| `memberCount: "12"` | `memberCount: 12` （数字は `"` で囲まない） |
| 全角スペースで字下げ | **半角スペース**を使う |
| `status: 活動中` | `status: "active"` （`active` か `done`） |

間違えた場合、`npm run build` が**どのファイルの何が悪いか**を教えて止まります。
壊れたまま公開されることはありません。
